Reflexión

1. ¿Qué ventajas ofrecen las variables CSS sobre los valores hardcodeados?
Permiten reutilizar valores como colores o tamaños en todo el sitio. Esto facilita cambios rápidos y hace el código más organizado y fácil de mantener.

2. ¿En qué casos conviene declarar variables CSS fuera del selector :root?
Cuando solo se necesitan en una sección específica, por ejemplo dentro de un componente o clase, para no afectar todo el sitio.

3. ¿Cómo se pueden utilizar las variables CSS para implementar un sistema de temas (como modo oscuro)?
Se pueden definir colores con variables y luego cambiar sus valores en otra clase o selector, como un modo oscuro, para que todo el diseño cambie automáticamente.

4. ¿Qué sucede cuando intentas usar una variable CSS que no ha sido declarada?
El navegador no aplica ese valor y puede usar uno por defecto o ignorar la propiedad.

5. ¿Cuál es la diferencia entre los enfoques mobile-first y desktop-first?
Mobile-first empieza diseñando para pantallas pequeñas y luego se adapta a pantallas grandes. Desktop-first hace lo contrario.

6. ¿Qué breakpoints son los más comunes y por qué?
Los más comunes son 600px (tablet), 1024px (laptop) y 1280px (desktop), porque corresponden a tamaños típicos de dispositivos.

7. ¿Cómo afecta el viewport meta tag al diseño responsivo?
Permite que el sitio se adapte correctamente al tamaño de la pantalla del dispositivo, especialmente en celulares.

8. ¿Qué técnicas además de media queries existen para crear diseños responsivos?
Usar unidades relativas como %, rem, flexbox, grid y layouts flexibles que se ajustan automáticamente.

9. ¿Cómo puedes identificar qué regla CSS está siendo aplicada cuando hay múltiples selectores?
Usando DevTools del navegador, donde se puede ver qué estilos se aplican y cuáles son sobrescritos.

10. ¿Qué información proporciona la pestaña Computed en DevTools?
Muestra los valores finales de cada propiedad CSS que realmente se están aplicando a un elemento.

11. ¿Cómo puedes simular diferentes dispositivos sin tener acceso físico a ellos?
Usando las herramientas de desarrollador del navegador (DevTools) que permiten cambiar el tamaño de pantalla y simular dispositivos.

12. ¿En qué situaciones es preferible usar Bootstrap sobre Tailwind CSS y viceversa?
Bootstrap es útil cuando quieres rapidez con componentes ya hechos. Tailwind es mejor cuando quieres más control y personalización del diseño.

13. ¿Qué significa que Tailwind sea "utility-first"?
Significa que usa clases pequeñas y específicas para aplicar estilos directamente en el HTML, en lugar de escribir mucho CSS personalizado.

14. ¿Cómo afecta el uso de un framework CSS al tamaño final del bundle?
Puede aumentar el tamaño del proyecto si no se optimiza, ya que incluye muchas clases o estilos.

15. ¿Es posible combinar múltiples frameworks CSS en un mismo proyecto? ¿Por qué sí o por qué no?
Sí es posible, pero no se recomienda porque puede causar conflictos de estilos y hacer el código más difícil de mantener.
